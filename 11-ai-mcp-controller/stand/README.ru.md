# Tibbo MCP Stand - ИИ управляет настоящим железом Tibbo

> ### ⚠️ БЕТА - требуется доработка
> Проект собран и проверен целиком на **эмуляторе платы**: 27 автотестов, официальный MCP-клиент Python SDK,
> панель на компьютере и телефоне. **На настоящей Tibbo LTPP3(G2) он ещё не запускался.** Для последнего шага
> нужен человек с платой на столе, и, возможно, это **вы**.
>

## Наткнулись на этот репозиторий случайно? Отлично, мы на это и рассчитывали

Большинство ИИ-демо заканчиваются на экране. Это - выходит за его пределы: **щёлкает настоящим реле,
читает настоящий датчик и замечает, когда по коробке постучали**. Контроллер - Tibbo LTPP3(G2): Linux на
плате с модулями-Tibbit, которые вставляются как кубики. Протокол - MCP, открытый стандарт, через который
любая нейросеть вызывает инструменты. Нейросеть - любая: Claude, ChatGPT, DeepSeek, Kimi, GLM, YandexGPT
или модель на ноутбуке вообще без интернета.

Скелет работает. Осталась первая встреча с настоящим железом и всё, что из неё вырастет. Каждый пункт ниже
можно сделать за вечер:

- **Есть LTPP3(G2)?** Запустите `python3 -m tibbo_mcp --probe` и откройте
  [отчёт с железа](../../issues/new?template=hardware-report.md). Сейчас это самый ценный вклад.
- **Разбираетесь в GPIO и I²C на Linux?** Сверьте наш код для sysfs и `/dev/i2c` с настоящей платой или
  перепишите его на libgpiod.
- **Любите ИИ-агентов?** Попробуйте другие модели, подкрутите системный промпт и пришлите диалоги, где
  модель запуталась.
- **Делаете интерфейсы?** Панель - один HTML-файл без зависимостей. Сделайте её двуязычной, добавьте
  графики или голос.
- **Есть идея, до которой мы не додумались?** Откройте issue. «А было бы круто, если…» - отличный заголовок.

Загляните в [CONTRIBUTING.md](CONTRIBUTING.md) и напишите нам. Авторов каждого принятого PR благодарим
в описании релиза.

## Что умеет

Четыре режима: от коробки без сети до флота площадок.

| Режим | Где нейросеть | Интернет | Что получаем |
|---|---|---|---|
| **1. Стенд без интернета** | на ноутбуке рядом с платой (Ollama, LM Studio, llama.cpp) | не нужен | выставочное демо, которое не зависит от Wi-Fi площадки |
| **2. Облачные нейросети** | Claude, ChatGPT, DeepSeek, Kimi, GLM, YandexGPT… | нужен; если пропал - **сама отвечает локальная модель** | самая умная модель, а стенд не замолкает без связи |
| **3. Плата как инструмент облачного ИИ** | в приложении нейросети или любом удалённом MCP-клиенте, через туннель | нужен | ИИ в телефоне читает датчики шоурума; **по умолчанию только чтение** |
| **4. Флот** | одна нейросеть - много плат (`fleet_status`, `fleet_call`) | локальная сеть или VPN | «На какой из наших 12 площадок перегрев?» |

И функция, которая делает из ИИ не собеседника, а инженера:

### Правила: ИИ пишет автоматику, плата её выполняет
Скажите: *«если дверь шкафа открыта дольше 10 секунд - включай лампу на минуту»*. Нейросеть создаёт правило
через `create_rule`, и дальше **плата выполняет его сама** при каждом опросе датчиков, даже если нейросеть
выключить. Правила проходят те же защиты, что и ручные команды: таймеры реле, аварийная кнопка,
«только чтение».

### Инструменты MCP

| Инструмент | Что делает | Железо |
|---|---|---|
| `stand_status` | что подключено, режимы, температура процессора | плата |
| `read_climate` | температура и влажность | Tibbit #30 (HIH6130) |
| `read_light` | освещённость | Tibbit #28 (BH1721) |
| `read_motion` | наклон, удары, «стучали ли по коробке» | Tibbit #36 (ADXL312) |
| `read_inputs` | кнопка и дверь шкафа, счётчики срабатываний | Tibbit #54 |
| `recent_events` | журнал событий | - |
| `set_relay` | лампа и вентилятор, всегда с таймером | Tibbit #03 |
| `set_leds` | 5 синих светодиодов платы: уровень или узор | плата |
| `create_rule` / `list_rules` / `delete_rule` | правила автоматики, которые выполняет плата | - |
| `check_tps_config` | проверка платы TPS посетителя и её картинка | [tibbo-ai-skills](https://github.com/SCANCODE-IOT/tibbo-ai-skills) |
| `find_tibbit` | поиск по каталогу из 84 Tibbit | tibbo-ai-skills |
| `lint_tibbo_code` | ловит выдуманные имена API в Tibbo BASIC / C | tibbo-ai-skills |
| `fleet_status` / `fleet_call` | другие платы флота (режим диспетчера) | - |

Чистый Python 3.9+ без сторонних библиотек: на плату ничего не нужно ставить через pip.

## Быстрый старт: эмулятор, 2 минуты, без железа

```bash
git clone https://github.com/SCANCODE-IOT/tibbo-mcp-stand
git clone https://github.com/SCANCODE-IOT/tibbo-ai-skills     # проверки плат и кода
cd tibbo-mcp-stand
python3 tools/mock_ollama.py --port 11434 &                    # заглушка нейросети или настоящая Ollama
python3 -m tibbo_mcp --sim --listen 127.0.0.1:8080
```

Откройте http://127.0.0.1:8080/. В эмуляторе лампа светит в датчик света, вентилятор охлаждает шкаф,
а на панели есть кнопки «Постучать по коробке», «Дверь», «Аварийная кнопка». Панель сотрудника - `/?staff`.
В Windows вместо `python3` пишите `python`, а заглушку запустите в отдельном окне терминала.

С настоящей локальной моделью: `ollama pull qwen3:14b` (около 9 ГБ, нужна видеокарта от 12 ГБ памяти),
скопируйте `config.example.json` в `config.json`, укажите `llm.url` = `http://127.0.0.1:11434` и
запустите `python3 -m tibbo_mcp --config config.json --sim`.

## Режим 1: стенд без интернета

Нейросеть на плату не помещается: у LTPP3(G2) 512 МБ памяти. Она работает на ноутбуке или мини-ПК в сети
стенда, а плата обращается к ней по адресу из `llm.url`. Чтобы Ollama принимала запросы из сети, задайте
переменную окружения `OLLAMA_HOST=0.0.0.0` и перезапустите её. Модели меньше 7-8 млрд параметров часто
путаются в инструментах, а без видеокарты ответ идёт минутами.

## Режим 2: облачные нейросети с запасной локальной

Возьмите `config.cloud.example.json`. Модели из `llm_chain` пробуются по порядку. Если сервис недоступен
(нет интернета, ошибка 5xx или 429), отвечает следующая. Ключи держите не в файле, а в переменных окружения:
их читает поле `api_key_env`.

```json
"llm_chain": [
  {"name": "claude", "api": "anthropic", "model": "claude-sonnet-5-5", "api_key_env": "ANTHROPIC_API_KEY"},
  {"name": "local",  "api": "ollama", "url": "http://192.168.10.2:11434", "model": "qwen3:14b"}
]
```

Готовые настройки (`api` + `url`) - в [docs/providers.md](docs/providers.md): Anthropic, OpenAI, DeepSeek,
Kimi (Moonshot), GLM (Z.ai), YandexGPT, ГигаЧат (через `gpt2giga`), OpenRouter, LM Studio, llama.cpp, vLLM.
Актуальные имена моделей смотрите в документации каждого сервиса.

На панели под каждым ответом видно, какая модель ответила: облачная или локальная.

## Режим 3: плата как инструмент облачного ИИ

Облачной нейросети нужен публичный адрес с HTTPS. Проще всего - быстрый туннель Cloudflare на плате или
на ноутбуке:

```bash
cloudflared tunnel --url http://localhost:8080
# -> https://<случайное-имя>.trycloudflare.com
```

Задайте в настройках длинный случайный `mcp.secret_path`. Тогда адрес MCP -
`https://<случайное-имя>.trycloudflare.com/mcp/<secret_path>`, его указывают в клиенте, который подключает
удалённые MCP-серверы по адресу. Клиентам, которые умеют передавать заголовки, подойдёт `/mcp` с
`Authorization: Bearer <token>`. Для постоянной работы - именованный туннель Cloudflare или обратный
SSH-туннель на свой сервер (например, `mcp.tibbo.ru`; nginx должен передавать `X-Forwarded-For`).

Через туннель (запросы с заголовками `Cf-Connecting-Ip` или `X-Forwarded-For`) сервер:
- отдаёт **только MCP**, а панель и чат доступны лишь в сети стенда;
- работает **только на чтение**, если не включить `mcp.internet_write: true`.

Проверено с официальным MCP Python SDK. Конкретные облачные приложения - в списке «нужно проверить».

## Режим 4: флот

Запустите узел-диспетчер с `config.hub.example.json` и перечислите адреса MCP других плат с токенами.
Диспетчером может быть плата, ноутбук или сервер. Нейросеть получает `fleet_status` (сводка по всем площадкам,
запросы идут параллельно) и `fleet_call(board, tool, arguments)`. Управление удалёнными площадками
выключено, пока не задано `fleet_write: true`, и каждая плата всё равно соблюдает свои защиты.

## На настоящей плате (LTPP3(G2))

Подбор: надёжно и без переплаты. Встроенный источник платы на 8-60 В питает всё, Tibbit-источники не нужны.

| Сокеты | Tibbit | Зачем |
|---|---|---|
| S3 + S4 | #00-3 + #30 | температура и влажность |
| S5 + S6 | #00-3 + #28 | освещённость |
| S7 + S8 | #00-3 + #36 | акселерометр |
| S9 + S10 | #03-1 + #21 | реле: лампа и вентилятор 12 В |
| S11 + S12 | #54 + #21 | кнопка, геркон двери, аварийная кнопка |
| *для расширения:* S13 + S14 | #05 + #21 | RS-485, счётчик по Modbus |

Ещё понадобятся: адаптер 12 В / 2 А, лампа и вентилятор на 12 В, грибок аварийной остановки, геркон, небольшой
роутер для сети стенда и монитор. Если на стенде будет насос или мотор, вместо #03 ставим #06.

```bash
python3 -m tibbo_mcp --probe     # ищет шины I2C и датчики, читает /opt/tps-shared/hwini/pins.ini
sh deploy/install.sh             # ставит в /opt/tibbo-stand и запускает службу systemd
```

**Что ещё не проверено на железе - тут нужны вы:** номера шин I²C, нумерация GPIO из `pins.ini` (как
в библиотеке Tibbo `node-ltps`), полярность реле и входов, интерфейс модуля ядра `tpsleds` и версия Python в
образе платы. Адреса датчиков I²C взяты из тестовых проектов Tibbo CA-Test-Tibbit-28/30/36.

Хитрость для выставки: когда стенд настроен, включите на LTPP3(G2) **оверлей** корневой файловой системы.
Тогда любая перезагрузка вернёт стенд к чистому рабочему состоянию.

## Безопасность

- Реле включаются только с таймером: по умолчанию не дольше 10 минут, потом выключаются сами.
- Не чаще раза в 2 секунды на одно реле и не больше 20 переключений в минуту.
- **Аварийная кнопка** на входе #54 сразу выключает всю нагрузку и запрещает включение.
- **Режим «только чтение»**: ИИ видит датчики, но ничего не включает.
- При остановке сервера все реле выключаются.
- Запросы с чужих сайтов (заголовок `Origin`) отклоняются: страница в браузере не сможет управлять стендом.
- Клиентам из интернета доступен только MCP, по умолчанию на чтение.

## Как устроено

```
tibbo_mcp/mcp.py      протокол MCP (stdio и Streamable HTTP), без зависимостей
tibbo_mcp/hal.py      эмулятор и драйвер LTPP3(G2): GPIO через sysfs, /dev/i2c через ioctl, /proc/tpsleds, --probe
tibbo_mcp/stand.py    опрос датчиков, события, защиты реле
tibbo_mcp/rules.py    движок правил автоматики
tibbo_mcp/fleet.py    маленький MCP-клиент и диспетчер флота
tibbo_mcp/agent.py    мост к нейросетям: Ollama, формат OpenAI, Anthropic, цепочка запасных
tibbo_mcp/web.py      HTTP-сервер: панель, /mcp, чат, события для экрана
tibbo_mcp/static/     панель (один HTML-файл, работает без интернета)
tools/mock_ollama.py  заглушка нейросети для тестов и репетиций
tests/                python3 -m unittest discover -s tests
```
